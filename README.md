# Ink To Card

MarginNote 4 经典插件，作者 **乔木Joe**。当前版本为 **1.0.4**。自动分析每张卡片最后一条手写绘图中的笔色，按学习集内的映射设置卡片 `colorIndex`，支持选中卡片和整个学习集批量处理。纯本地识别，无需 AI、API Key 或 MN Utils。

本次正式包为 `Ink To Card 1.0.4.mnaddon`，保留已有 1.0.0–1.0.3 正式包。补充点状短笔画、已核对图形曲线和蓝色短笔画的兼容，修复这些绘图导致整张卡片无法识别改色的问题，适用于单卡、自动跟随和批量处理。

正式安装包可从 [GitHub Releases](https://github.com/642827083/Ink-To-Card/releases) 下载。面板底部显示插件名称、作者和版本号。

## 当前功能

1.0.4 根据三份 MN 4.5.0 / build 64 样本补充兼容：布局 1 的单点笔画使用公共头偏移 4 的笔宽；布局 131 使用 14 字节点记录和 20 字节公共头；带字段 13/14 的图形除等宽直线外，支持布局 3、32 点、首尾外逐对重复的已核对曲线。坐标按原样保留，长度、笔宽、未知字段与路径标记检查继续执行。真实样本分别为 621、70、61 条笔画，覆盖完整解析及单卡、自动和批量改色命令。

“颜色映射”末尾保留“无彩色书写”映射行，默认“不触发”。它与现有三种颜色模式配合使用，适用于单卡、自动跟随和批量。

单击图标等待约 0.3 秒区分双击后开合面板；双击取消待执行的单击，开启／关闭当前学习集的自动跟随并收起面板。自动跟随开启后图标常亮，不依赖面板是否显示。开关保留原有绿色，动画放慢为约 0.32 秒，继续尊重系统“减少动态效果”设置。按钮与自绘开关不叠加原生按压外观；处理中保留防重复点击但保持亮度稳定。

1.0.3 根据用户核对正确的 94 笔预览，开放对应路径标记的识别与改色，适用于单卡、自动和批量，并覆盖此前两份 MN4.5.0 / build 62 样本。兼容限于已核对的通道布局 39/103/167/231，非零标记须小于该笔画点数；不利用该字段裁剪、重排或丢弃笔画，其完整语义仍未确认。超出范围时保留只读试验预览，其余格式和完整性检查继续执行。

## 安装与使用

1. 在 MN4 的插件设置中导入 `Ink To Card 1.0.4.mnaddon`，沿用原插件身份与本地配置。
2. 打开学习集，点击 Ink To Card 插件图标。先在脑图中选定一张卡片，插件会记住它；取消选中或进入该卡片编辑后仍继续跟踪。单选另一张卡片时切换目标，多选时保留当前目标。面板显示“当前跟踪卡片”，可核对正在处理哪张卡。
3. “手写来源”自动选择批注排列顺序中的最后一条绘图，可点击“预览”查看。无需逐卡指定，普通图片不会参与自动选择。
4. 展开“颜色映射”，设置笔色对应的卡片色号。例如，先在 MN 中把任意卡片设成想要的红色，并在脑图中选中它，再在红色一行点击“取当前卡色”。也可手动选择 1–16 的色号，与 MN 色板显示一致。色号含义取决于当前学习集的色板，初次安装全部设为“不触发”。
5. 在“识别规则”选择颜色模式。“有红色就设为红色”仅要求红色达到最低笔迹量，不要求占多数；没有足量红色则保持原色。请先设置红色的目标色号。
6. 需要把全黑等无彩色书写标为已做对时，在映射末尾的“无彩色书写”选择目标色号，或点击该行的“取当前卡色”。确认最后一条绘图有足量可见手写，且没有检测到彩色时才使用它；黑、灰、白均适用。检测到少量彩色、彩色未映射、多色冲突、没有绘图或读取失败时都不触发这条规则。
7. 点击“立即识别并改色”，或启用“自动跟随笔色”；双击插件图标也可切换自动跟随。也可展开“批量处理”，多选脑图卡片后点“处理选中卡片”，或点“处理当前学习集”。设置按学习集保存。

自动模式约每 0.3 秒轻量读取当前目标，媒体或设置变化后，至少等待 300 毫秒再次确认稳定才解析和改色。相比原先每 1.2 秒检查缩短了检测等待；通常两次检查需要约 0.3–0.6 秒，还需要 MN 保存笔迹和图像解析的时间，不能保证落笔后 0.3 秒完成。只有稳定的新媒体才解析图片，不每次检查都读取媒体。

收起面板后继续跟踪。MN 进入后台时暂停，返回前台后重新确认稳定再继续；离开学习集会清除记住的卡片，重新进入后需先选定目标。切换学习集、后台及窗口关闭会使旧识别结果失效。目标仅在当前窗口会话中保留，不跨学习集或重启记忆。旧版手动来源绑定不参与识别，已有颜色映射继续保留。

批量不需要逐卡选中或打开。选中模式只处理选中的卡片；整个学习集模式遍历根卡片、子卡片及子脑图并去重，不跟随其他学习集的链接。一次最多 5,000 张卡。逐卡显示进度、汇总改色与跳过数量，最多显示 50 条跳过原因；无绘图、格式不支持或媒体缺失时跳过该卡。取消只停止剩余处理，已完成的改色可逐张撤销。切换学习集、进入后台或设置变化会停止整批任务。

改色作为一次 MN 撤销操作执行。相同媒体与相同设置不会在当前插件会话里反复改色，撤销和手动改色不会立即被自动模式覆盖；主动点击识别可再次处理。插件重新加载后，自动模式会重新检查当前卡片。

当前色号、映射下拉框和改色提示统一显示为 1–16；内部接口与已保存的映射仍使用 0–15 索引。此次只修正显示编号，实际对应颜色保持不变，已有映射无需重新设置。例如原先显示“色号 7”的同一个颜色，现在显示为“色号 8”。

## MN4 的能力边界

- 公开文档把手写和导入图片都归为 `PaintNote`，不能单凭类型区分。自动识别只选择带 `drawing` 字段的最后一条批注，并要求媒体能按已验证的笔画格式解码；不把普通 `paint` 图片当成手写。不支持的最后绘图会跳过，不回退到较早绘图。
- `drawing` 的已验证 PencilKit `wrd` 格式直接从笔画记录还原笔色和坐标，只渲染笔迹，不包含题目底图。当前仅接受样本验证的普通笔、通道布局及等比例变换；未知笔刷、遮罩、路径标记、存储版本或额外字段会报错，不能带着不完整结果继续改色。
- 绘图预览以控制点折线和平均笔宽近似渲染；不是 PencilKit 的原生曲线和笔刷纹理，像素面积会有差异。绘图限制为 3,000 条笔画、40,000 个控制点。
- 以普通图片形式保存的手写不参与当前自动识别。独立脑图草稿和文档画布笔迹尚未接入。
- 不是 OCR：不识别文字内容、笔画先后或“最后一笔”。绘图从每条笔画的笔色表读取颜色，生成预览后统一按彩色像素面积计算。
- 黑、白、灰不参与彩色投票；“无彩色书写”有独立映射，默认关闭。启用后要求可见手写像素达到同一最低量、彩色像素严格为零，并由原生层重新解码确认有效笔画及原始笔色中没有彩色。近透明笔迹不计入有效可见量。彩色笔迹不足最低量时仍保留卡片原色，不使用无彩色映射。主要颜色占比默认需达到 60%，多色接近时跳过。优先级模式依次为红、橙、黄、绿、青、蓝、紫，仅启用已映射的颜色。红色模式只检查红色，不回退选择其他颜色；所有模式的最低有效像素门槛为 `max(minPixels, 分析图像像素数 × minRatio)`，默认 `minPixels=30`、`minRatio=0.00005`。
- 只调整 `colorIndex`；卡片在脑图中的实际显示还受 MN 卡片样式控制，颜色变化可能传播到关联摘录。
- 每次读取都重新选择最后绘图。识别期间最后绘图的位置或媒体变化、卡片颜色被手动修改时拒绝过期结果。单卡和自动模式读取已记住的目标，不要求它继续被选中；新单选切换目标、窗口会话、学习集或活动状态变化时拒绝旧结果。
- 媒体缺失、解码失败、超过 12 MB、像素超过 2400 万、撤销 API 缺失时不进行改色，并在面板显示原因。

已有 MN4 真机样本验证了 `drawing` 媒体读取与导出；本地已验证真实绘图解析、笔色计算、原生接口替身、取消选中后跟踪、新单选切换目标、虚拟时钟下的 300 毫秒稳定等待、生命周期、批量取消及经典安装包启动。替身测试不代表 MN4 真机已经成功。

若页面曾一直显示“正在读取”，请重新导入更新后的安装包并重启 MN。网页使用的全部脚本现已放入入口目录，避免本地 WebView 拒绝读取上级目录；页面启动错误会显示具体原因，原生桥接 20 秒未响应会显示“读取失败，点击刷新”。

卡片标题与色号能显示但没有来源时，点击“检查手写来源”。该检查分别读取焦点对象和数据库对象的批注类型、PaintNote 总数、`paint` / `drawing` 来源数、`getStrokesCount` 和 `getDrawingSize`，并显示 MN 版本。最多读取三条 drawing 媒体，报告大小、文件头格式、图片或笔画解码结果，不返回正文、媒体哈希或原始字节。内嵌对象和未验证的二进制格式仍不支持。

MN 4.5.0 / 60 的真机测试先确认 `drawing` 媒体可读但不能用 UIImage 解码。随后用户导出的 80,549 字节样本确认了 `wrd` 格式，包含 150 条笔画、2,899 个点，黑色 73 条、红色 77 条；本地已还原预览并识别为红色。当前版本沿用该独立绘图读取与解析，通过经典 UIWebView 桥接调用原生层。解析器未依赖原生 PKDrawing 或第三方运行库；它针对已验证的存储格式，不是公开稳定的 PencilKit 序列化协议。

另一份 51,519 字节样本含 88 条笔画、1,970 个点，黑色 84 条、红色 4 条。两条水平直线带有字段 13 / 14，已按该样本核对并兼容；后续 build 64 样本表明同类字段也会出现在曲线上，因此 1.0.4 补充已核对的等宽配对曲线结构。字段完整语义尚未公开，其他组合仍报错。已恢复原有全部笔画并核对截图中的红色“取反”，实际识别与改色需在 MN4 中验证。

仍可点击“导出绘图样本”。插件在自己的临时目录写入 JSON，通过 MN 的保存窗口导出，包含最后一条绘图的完整 Base64、字节数、尺寸和宿主版本，用于排查新格式；不包含其他批注或卡片正文。最多导出 1 MB，导出不修改卡片。请求打开保存窗口并不代表用户已经完成保存。

## 开发

```sh
npm run check
npm test
npm run build
npm run build:release
```

默认只生成 `Ink To Card Test.mnaddon`。正式版本由用户测试成功后指定；`npm run build:release` 拒绝发布 `0.0.0`，也拒绝覆盖已有正式包。

`src/` 在 JavaScriptCore 中运行，`web/` 在经典 UIWebView 中运行。只有 `main.js` 使用 `JSB.require`；入口加载 `InkToCardAddon`、`InkToCardPanel` 与独立的 `InkToCardToolbar`，用 `NSTimer` 驱动检查和单击／双击判定，通过 iframe 自定义协议分发到 `src/WebBridgeCommands.js`。设置由原生 `NSUserDefaults` 保存，网页不保存业务数据。`mapping.uncolored` 是新增的可选映射，旧设置读取时默认为 -1；七种彩色统计与优先级继续只使用原有颜色列表，映射列表另包含“无彩色书写”。`InkToCardBatch.js` 保存当前窗口的临时批量任务，每次写入均校验任务、学习集、设置、最后绘图和原卡色。

用户允许使用 MN5 接口，但插件必须保持 MN4 经典结构；引入新接口前检查宿主支持情况，并在交付说明中列明实际调用。本次两项优化使用经典原生接口完成，没有使用 MN5 专用接口。之前的 `InkToCardSceneAddon.js` 与 `inkFollow.js` 源码保留作场景方案参考，不进入安装包，不由当前入口加载。

构建时将共享配置和识别算法复制到包内的 `web/`，两份产物均来自 `src/` 单一源码。`npm test` 先重建测试包，再验证安装包在限定入口目录的加载方式与桥接响应。

浏览器演示使用 `scripts/preview.cjs` 启动本地预览，打开 `/web/index.html?demo=1`。演示数据只在内存中，演示桥接不包含在安装包内。

## 接口依据

首先查阅[当前官方文档](https://dev.marginnote.com.cn/zh/introduction)，核对[插件基础](https://dev.marginnote.com.cn/zh/plugin-base)中经典插件与场景插件的入口差异。当前版本采用经典 `main.js` 入口与自建面板，不声明场景面板或场景事件。经典原生接口在新站未覆盖时再查旧站。

原生绘图及持久化接口参考：

- [MbBookNote](https://mn-docs.museday.top/reference/marginnote/mb-book-note/)：批注、颜色索引与笔记身份。
- [NoteComment](https://mn-docs.museday.top/reference/marginnote/note-comment/)：`PaintNote.paint` 是媒体哈希。
- [Database](https://mn-docs.museday.top/reference/global/database/)：`getMediaByHash` 与 `getNoteById`。
- [MindMapView](https://mn-docs.museday.top/reference/marginnote/mindmap-view/)：`selViewLst` 提供选中节点。
- [MbTopic](https://mn-docs.museday.top/reference/marginnote/mb-topic/)：`notes` 提供根卡片；子卡片和子脑图使用 `MbBookNote.childNotes`、`childMindMap`。
- [官方 Addon API 头文件](https://github.com/marginnoteapp/Addon/tree/master/API)：UIImage 解码/PNG 导出、NSData Base64、UIWebView 与 NSTimer 的导出名称。
- [UndoManager](https://mn-docs.museday.top/reference/utility/undo-manager/)：分组撤销。
- [libfreeform 原作者解析源码](https://github.com/can1357/libfreeform/blob/main/src/pkdrawing.rs)：交叉核对 `wrd` 存储字段；本项目通过真实 MN4 样本验证支持范围，自行实现解析及近似预览。这不是 MarginNote 官方接口。

参数以实际宿主支持的接口为准；测试替身不代表真机运行成功。
